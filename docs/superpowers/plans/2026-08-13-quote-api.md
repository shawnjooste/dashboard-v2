# Quote API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A keyed REST API (`/api/v1/`) over `lib/quotes/service.ts` so the team and Hermes can draft and amend quotes that always land in `pending_review` — no send route exists.

**Architecture:** Thin Next.js route handlers → `lib/api/auth.ts` (hashed key → gated `Actor`) → `lib/quotes/api-input.ts` (pure assembler: varying parts + template → `CreateQuoteInput`) → the existing `makeQuoteService(sb)`. No quote rules in routes.

**Tech Stack:** Next.js 15 App Router route handlers, Supabase (Postgres, service role), `node:crypto` sha256, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-13-quote-api-design.md` — the plan argues from it; read both.

## Global Constraints

- Supabase project ref is `eskhokedsximnslgsycs`; migrations via `supabase db push` (repo already linked, no `--project-ref`), then `supabase gen types typescript --linked > lib/types/database.ts`.
- Never print or commit `.env.local` contents or any credential value. A minted API key may be printed ONCE by the mint CLI to its operator — never logged, never stored plaintext.
- Shared pure modules (the assembler) carry no `import "server-only"` and no `@/…` aliases — relative `.ts` imports, dependencies as parameters. Auth + routes are Next-only and may use both.
- Every API-created or API-amended quote lands in `pending_review`: the Actor is always `{ id: key.profile_id, label: key.name, canSend: false }`. `canSend` is hardcoded — not a column, not a scope.
- Markup rule (server-side only): `unitPrice = round2(supplierCostExVat × 1.15)`.
- Standard terms always appear, in order; `extraTerms` append only. Checkout swaps the payment term to the card wording.
- Error shape everywhere: `{ "error": string }` (+ `candidates` on 409, + `details` on 422). 401 for missing/unknown/revoked key, indistinguishable.
- Run `npx vitest run` before every commit (593 tests green at time of writing). Pre-existing tsc errors in `lib/views/status.ts`, `app/(app)/layout.tsx`, `lib/actions/status.ts`, `.next/types` are not yours.
- Tests never send email and never write to the live database: mock `deliverEmail` (`vi.mock` of `lib/email/deliver.ts`, per `lib/quotes/service.create.test.ts`) and stub the Supabase client. The single live pass is Task 6, scratch `QU-ZZZ` rows only.
- Other agents commit to this working tree in parallel: stage only files you touched; check `ls supabase/migrations | tail -3` immediately before writing a migration and renumber on collision (0092 free at time of writing).

### Task 1: `api_keys` migration + key CLI

**Files:**
- Create: `supabase/migrations/0092_api_keys.sql`
- Create: `scripts/api-key.mjs`

**Interfaces:**
- Consumes: nothing.
- Produces: table `api_keys(id, name, key_hash, key_prefix, profile_id, created_at, last_used_at, revoked_at)`; key format `rk_live_<32 url-safe chars>`; hash = hex sha256 of the FULL key string.

- [ ] **Step 1: Check the migration number, write the migration**

Run `ls supabase/migrations | tail -3`; renumber if 0092 is taken.

```sql
-- API keys for the scoped quote API. Service-role only (RLS on, no policies,
-- matching quote_prefix_counters). Only the sha256 of a key is stored; the
-- key itself is shown once by scripts/api-key.mjs and never again.
create table public.api_keys (
  id           uuid primary key default gen_random_uuid(),
  name         text not null,
  key_hash     text not null unique,
  key_prefix   text not null,
  profile_id   uuid references public.profiles(id) on delete set null,
  created_at   timestamptz not null default now(),
  last_used_at timestamptz,
  revoked_at   timestamptz
);
alter table public.api_keys enable row level security;
```

Run: `supabase db push` then `supabase gen types typescript --linked > lib/types/database.ts`.
Expected: `grep -c api_keys lib/types/database.ts` is non-zero.

- [ ] **Step 3: Write `scripts/api-key.mjs`**

Follow the house script shape (env loading via `readFileSync(new URL("../.env.local", import.meta.url))` exactly as `scripts/create-quote.mjs` does). Subcommands:

```
node scripts/api-key.mjs mint "Hermes"                      # no profile
node scripts/api-key.mjs mint "Kelle" --profile kelle@rocking.one
node scripts/api-key.mjs list
node scripts/api-key.mjs revoke <key-id>
```

Mint: `const raw = "rk_live_" + crypto.randomBytes(24).toString("base64url");` (24 bytes → 32 chars), `key_hash = createHash("sha256").update(raw).digest("hex")`, `key_prefix = raw.slice(0, 12)`. `--profile` resolves a profiles row by email (ilike) and errors listing candidates if not exactly one. Print the raw key once with a warning that it will never be shown again. List prints id, name, key_prefix, profile email or "—", created/last-used/revoked. Revoke sets `revoked_at = now()` (idempotent; report if already revoked).

Mint `"__plan-test"`, list (shows it), revoke it, list (shows revoked), then delete the row by id with a one-off scratch script. Expected: table returns to prior row count.

### Task 2: Template constants + pure assembler

**Files:**
- Create: `lib/quotes/api-template.ts`
- Create: `lib/quotes/api-input.ts`
- Test: `lib/quotes/api-input.test.ts`

**Interfaces:**
- Consumes: `type { QuoteDoc, QuoteItem } from "./doc.ts"`; `type { CreateQuoteInput, AmendQuoteInput } from "./service.ts"`; `computeTotals` from `./doc.ts` (tests only).
- Produces:

```ts
// api-template.ts (no imports, pure constants)
export const COMPANY: QuoteDoc["company"];        // Rocking (PTY) LTD block, VAT 4810312173, reg 2013/047237/07
export const BANKING: QuoteDoc["banking"];        // FNB 63023869192, Blue Route Mall branch, 250655
export const STANDARD_TERMS: readonly string[];   // validity, ex-VAT, payment-prior-to-order, ownership-until-paid
export const CHECKOUT_PAYMENT_TERM: string;       // "Payment is made online by card using the payment button on this quote."
export const EFT_PAYMENT_TERM: string;            // "Payment is due prior to order placement."
export const VALIDITY_DAYS = 14;

// api-input.ts (marker-free; relative .ts imports only)
export type ApiQuoteItem = {
  description: string; detail?: string; qty: number;
  supplierCostExVat?: number; unitPriceExVat?: number; monthly?: boolean;
};
export type ApiCreateBody = {
  client?: string; clientId?: string; title: string; items: ApiQuoteItem[];
  intro?: string | null; summaryNote?: string | null; extraTerms?: string[];
  attention?: string | null; validUntil?: string | null;
  checkout?: boolean; billingStartsNextMonth?: boolean;
};
export type ApiAmendBody = Omit<ApiCreateBody, "client" | "clientId" | "checkout" | "billingStartsNextMonth">;
export type ClientContext = {
  id: string; name: string; registeredName?: string | null;
  attention?: string | null;            // from client_company_details.billing_contact_name
  addressLines?: string[];              // from physical_address split on newlines
};
export type FieldError = { field: string; message: string };
export function round2(n: number): number;
export function assembleCreate(body: ApiCreateBody, client: ClientContext, opts: { today: Date; actorLabel: string })
  : { ok: true; input: CreateQuoteInput; internalNotes: string[] } | { ok: false; errors: FieldError[] };
export function assembleAmend(body: ApiAmendBody, client: ClientContext, opts: { today: Date; actorLabel: string })
  : { ok: true; input: AmendQuoteInput } | { ok: false; errors: FieldError[] };
```

Assembly rules (all enforced here, nowhere else):
- Validation → `{ok:false}` with one entry per problem: `title` non-empty; `items` non-empty; each item `qty >= 1`; each item exactly one of `supplierCostExVat`/`unitPriceExVat` (both → error, neither → error); `validUntil` if given parses as yyyy-mm-dd and is not before `today`.
- Pricing: `unitPrice = round2(supplierCostExVat * 1.15)` or `unitPriceExVat` as-is. `round2(n) = Math.round(n * 100) / 100`.
- Sections: non-monthly items → section `{id:"supply", title:"Section 1 — Supply", subtitle:"Supply only", totalLabel:"TOTAL (incl VAT)"}`; monthly items → `{id:"recurring", title:"Section N — Monthly Services", subtitle:"Billed monthly", totalLabel:"TOTAL MONTHLY (incl VAT)", monthly:true}`. Build only sections that have items; number their titles by position (a monthly-only quote has "Section 1 — Monthly Services").
- `internal`: for every item with a `supplierCostExVat`, emit `{path, supplierCost: round2(cost * qty), note}` — path computed from the section layout the assembler itself built (`s<idx>.g0.i<idx>`), supplierCost is the EX-VAT LINE TOTAL per the house convention, note = `"Supplier cost R<cost> ex VAT per unit (via API by <actorLabel>). Markup: cost × 1.15 = R<unitPrice> ex."`. Return matching human-readable strings as `internalNotes` for the route's response logging.
- Doc: `company: COMPANY`, `banking: BANKING`, `vatPercent: 15`, `client: { name: client.registeredName ?? client.name, attention: body.attention ?? client.attention ?? "", addressLines: client.addressLines ?? [] }`, `meta: { quoteNumber: "", date: <today as "13 August 2026">, validUntil: <same format>, preparedBy: actorLabel }`, `projectTitle: title`, `projectIntro: body.intro ?? "This quote covers <title>. All prices exclude VAT (15%)."` — when checkout, the generated intro ends ", payable online by card. All prices exclude VAT (15%)."
- Terms: `[validity, exVat, payment(checkout ? CHECKOUT_PAYMENT_TERM : EFT_PAYMENT_TERM), ...rest of STANDARD_TERMS, ...extraTerms]` — the assembler owns the order; extraTerms only ever append.
- `validUntil` default: today + VALIDITY_DAYS, emitted both as ISO (`input.validUntil`) and display format (`doc.meta.validUntil`).
- `assembleAmend` = same doc assembly minus checkout/billing flags (payment term uses a new `opts.checkout: boolean` passed from the quote row, so an amend of a checkout quote keeps the card wording).

```ts
// lib/api/auth.ts  ("server-only" allowed; Next-only)
export type AuthResult =
  | { ok: true; actor: Actor; keyId: string }
  | { ok: false };  // caller returns 401 {error:"unauthorized"}
export function hashApiKey(raw: string): string;               // hex sha256, pure, exported for tests+CLI parity
export async function authenticateApiKey(sb: SupabaseClient, authorizationHeader: string | null): Promise<AuthResult>;
```

Behaviour: header must be `Bearer rk_live_…`; sha256 it; select `id, name, profile_id, revoked_at` from `api_keys` by `key_hash`; missing row OR `revoked_at` set → `{ok:false}` (identical). Success → fire-and-forget `update({ last_used_at })` (a failure is console.error'd, never fails auth) and `{ ok:true, actor: { id: profile_id, label: name, canSend: false }, keyId }`.

Route behaviours:

- `GET /api/v1/quotes/[id]`: auth → quote by id (404) → current version totals row → `{quoteNumber, status, version, totals:{exVat, vat, inclVat, monthlyInclVat}, portalUrl, adminUrl}` (urls from `NEXT_PUBLIC_APP_URL ?? "https://portal.rocking.one"`).
